# 阈值合理性与精度评价流程

## 原因

`pseudo_labels1.js` 加入【改动34】后，Summary11 相比 Summary10 出现系统性下降：

- 18 场洪涝面积全部下降，总面积 589.42 → 202.54 km²（-65.6%）；
- High 像元数 -59.3%，Medium 像元数 -71.8%；
- 每 100 mm 雨量面积中位数 15.30 → 3.96 km²，低于 4 km²/100mm 的事件由 1 场增到 9 场。

这种下降有两种可能：一是新阈值正确剔除了事件前已有水体，二是阈值过严，连同真实新增洪水一起删掉。仅看 Summary11 无法区分。

因此需要重新做 `validation_review.js`，但重点不是简单重跑，而是把“新阈值标签生成 → 人工独立判读 → 阈值调优 → 重跑标签 → 独立验证”串成一条闭环。Summary10 在这里只是旧规则基线，用来量化改动影响，不是真值；最终合理性必须由人工 `reference` 判定。

---

## 完整链路（6 条）

### 1. 同步 `validation_review.js` 的判识规则

把 `validation_review.js` 的标签生成部分与 `pseudo_labels1.js` 的【改动34】保持一致，至少同步：

```javascript
VV_PRE_NONWATER_TH = -15
VH_PRE_NONWATER_TH = -23
VV_POST_WATER_TH = -16
VH_POST_WATER_TH = -22
```

并确认 `sarFlood` 同时要求事件前非水、事件后为水、相对下降超阈值。否则判读点仍按旧规则生成，无法评价 Summary11。

### 2. 重新设计抽样

不能只抽 Summary11 的 High Flood / Medium Flood / Non-Flood，需要覆盖至少四类：

1. Summary11 的 High Flood；
2. Summary11 的 Medium Flood；
3. Summary11 的非洪涝；
4. Summary10 判为洪涝、但 Summary11 因新阈值被删除的像元。

第 4 类用于判断“删掉的到底是旧水体还是真实洪水”，是本次阈值评价的关键。抽样按事件分层，并记录每个点所属的类别和规则版本。

### 3. 人工判读得到独立 `reference`

用 `validation_review.js` 对抽样点做盲判，填写独立 `reference`：

- `1` = Flood；
- `0` = Non-Flood；
- `-1` = Uncertain。

判读时不要显示伪标签，避免开卷偏差。按事件分层统计，记录 `confidence`。这部分 `reference` 是后续阈值合理性和精度评价的唯一真值来源。

### 4. 计算精度指标

以人工 `reference` 为真值，对比伪标签，重点计算洪涝类指标：

- Precision（误报 / commission）；
- Recall（漏报 / omission）；
- F1；
- IoU；
- 逐事件指标和总体指标。

非洪涝像元远多于洪涝像元，总体 Accuracy 会掩盖洪涝漏报，不能作为主要判据。重跑后变成 Unknown/掩膜的验证点要单独统计，不能直接当正确或错误。

### 5. 判断阈值是否合理

结合第 4 步指标判断：

- 如果新阈值显著提高 Precision，但 Recall 和 F1 大幅下降 → 阈值偏严；
- 如果 Precision 提高，Recall/F1 仍可接受 → 阈值合理；
- 同时检查删除的像元是否主要是事件前水体、季节性明水或泡田；
- 再结合面积/雨量关系和目视核查判断是否过度收缩。

Summary10 与 Summary11 的对比只用于归因和敏感性分析，不能替代人工 `reference`。

### 6. 调阈值后重跑标签，再做独立精度评价

把人工判读点分成两组：

1. **调阈值集**：用于标定 4 个新阈值；
2. **独立验证集**：不参与调参，用于最终精度评价。

用调阈值集确定阈值后，重跑 `pseudo_labels1.js` 得到新的标签版本（例如 `Summary12`），然后在**固定的验证点坐标**上提取新标签，与人工 `reference` 比较，计算 Precision / Recall / F1 / IoU。

最好按事件留出：调阈值的事件和验证的事件不要相同。调阈值点不能用于最终精度评价，Summary10 的标签也不能当作真值。

---

## 关键原则

1. Summary10 是对照基线，不是真值；
2. 人工 `reference` 是阈值合理性与精度评价的唯一真值；
3. 调阈值与最终验证必须分开，最好按事件留出；
4. 验证点要固定，重跑标签后在同一批点上提新标签；
5. 洪涝类 F1 / IoU / 漏报率优先于总体 Accuracy；
6. `flood_sens_ratio` 目前仍按旧候选规则计算，更新新约束前不能作为新阈值的稳定性依据。

## 2026-10-20 补充：当前可执行的流程（4 步）

上面 6 条是原则。截至 2026-10-20 的实际状态：

- 【改动42】已把 `VH_PRE_NONWATER_TH` 由 −20 dB 标定为 −23 dB，`validation_review.js` 与 `pseudo_labels1.js` 已同步；其余三条（−15 / −16 / −22）仍是参考初值。
- 【改动43】把主脚本 `SAMPLE_POINT_SCALE` 由 10 m 改为 30 m，与判读抽样尺度对齐，原先「30 m 标定结果不能回填主脚本」的阻塞消除。
- 已判读 385 点（`csvdata/validation_points/Wuhan_validation_reference202123.csv`，2020_0705 / 2021_0823 / 2023_0618 三场），其中前三层 135 点、差异层 216 点有效。
- 主脚本已按 −23 全量重跑，`Summary12` 已产出（`csvdata/pseudo_labels/Wuhan_2016_2025_Flood_Event_Summary12.csv`），18 场面积相对 `Summary11` 全部上升，总面积 202.54 → 291.77 km²。`Summary11` 已不是最新结果。

下面的顺序据此落到具体操作，成本由低到高。

### 步骤 1｜主脚本全量重跑，产出 `Summary12`（不做新判读）

`pseudo_labels1.js` 按 `VH_pre = −23` 全量重跑。

**理由**：这是目前唯一能证伪【改动42】的操作。阈值放宽（`vh_pre > -23` 比 `> -20` 更容易满足）意味着更多像元被认作事件前非水，全图面积理应大于 `Summary11`。若跑出来反而变小或不变，说明改动未按预期传导，后续步骤全部要重来。顺带产出各事件的分层像元数（【改动44】起六层），可作为步骤 3 的点数估算依据。

**验收结果（2026-10-20，已执行）**：`Summary12` 已产出，18/18 场面积上升（+28.49% ~ +114.59%），总面积 291.77 km²（相对 `Summary11` +44.06%，相对 `Summary10` 仍 −50.50%）。`n_nonflood_px` 合计 5,605,756.49 与 `Summary11` 完全相同，证明改动只落在正类生成路径。判读与分析见 `csvdata/pseudo_labels/事件筛查与训练集划分3.md`。

### 步骤 2｜换验证场（只改一个数组）

把 `validation_review.js` 的 `RUN_EVENT_NAMES` 换成 `VALIDATION_EVENT_NAMES` 中尚未判读的场。原计划取 `Wuhan_2016_0630` / `Wuhan_2017_0824` / `Wuhan_2025_0607`。

**理由**：当前最大的硬缺陷不是阈值不准，而是没有独立评价。【改动42】的留一事件三折（留 2020 / 留 2021 / 留 2023）已把 `Wuhan_2021_0823` 这个唯一 valid 场消耗掉，现在引用的 valid F1 .667 不能当独立结果。这一步不重抽旧三场，385 点全部保留；同时把 `Wuhan_2021_0823` 移出 `VALIDATION_EVENT_NAMES`，使现有 385 点整体降级为 tune，tune 与 valid 彻底不重叠。

若只能做一件事，就做这一步——它修的是结构缺陷，成本只是改事件名。

**【改动44】已执行（2026-10-20）**：实际取的是 **`Wuhan_2016_0630` + `Wuhan_2023_0719`** 两场，不是原计划三场。取舍依据是信息互补而非数量：`2016_0630` 面积最大（77.02 km²）、S2 有效覆盖仅 0.231（光学最弱）、本次新增面积占总新增 26.6%，SAR 信号可与光学隔离；`2023_0719` 面积最小（2.80 km²）、`per100` 最低（1.72）、S2 覆盖 1.00（光学最好）。`2017_0824` 因强制 L1C（TOA）暂缓，`2025_0607` 与 `2023_0719` 的 High 占比高度重复（93% vs 100%）故本轮不取。

### 步骤 3｜判读新场，差异层扩容 + 新增漏检层

原计划只把 `cut_prewater` / `cut_postweak` 由 40 改为 100、层 0/1/2 保持 20，单场上限 140 → 260。

**【改动44】已落地的是另一种组合**：新配额 `20 / 20 / 20 / 40 / 40 / 40`（六层，合计 200 点/场），即**新增第 5 层 `missed_optical`**、差异层本轮仍取 40。理由：`Recall` 恒为 1.000 是结构缺口（`new_label = 0 ∧ reference = 1` 的点一个都抽不到），补上这一层比单纯给差异层加点更能改变可用结论；差异层扩容留到下一轮。注意第 5 层给的是「漏检候选里真洪占多大比例」，它**不能直接并入 `Recall`**——该层是固定配额的非随机抽样、像元 `label = −1`，加权口径见下方第 2 条。

**配额 40/40/40 是临时值，未定稿。** 30 m 下各层格数比 10 m 少一个量级，`min(该层上限, 该层格数)` 会静默少抽，所以顺序必须是：先在 GEE 跑一次分层诊断看 `stratumHist` 各层实际格数，再定最终配额。

**必须说清的限度**：这一步不会让四个阈值变得「可标定」。差异层上四个变量的 AUC 是 `VV_post_c` 0.46 / `VH_post_c` 0.35 / `VV_pre` 0.25 / `VH_pre` 0.12（见 `csvdata/validation_points/判读结果分析与阈值评价_20261019.md` 第 3 节）。这是**判别力**问题，不是样本量问题：加样本只能收紧置信区间，不会改变 AUC 的量级。

实际收益是两件事：把「差异层误删率 22.2%」的区间收窄（当前真洪样本只有 48 个）；判清 `2020_0705` 的 `cut_postweak` 误删率 44.7% 与 `2023_0618` 同层 0% 这个矛盾属于事件差异还是抽样噪声。若确属事件差异，结论会变成「单一全局阈值不成立」——这比标定出一个数字更有价值，也直接推翻把四个阈值当全局常量的前提。

**不要重抽旧三场。** `point_id` 由事件名 + `system:index` 拼接（`validation_review.js:1522`），重跑即重排；而 `stratifiedSample`（`:1493`）在 `numPoints` 由 140 改到 220 后是否保留原子集，无证据、未验证。最坏情况是 216 个已判差异点全部作废。两批点按各自的每层配额分别记录即可（`stratum` 定义未变），不必为统一配额丢掉已判工作量。

### 步骤 4｜定阈值 → 回填 → 重跑 → 在 valid 上评价

在调参集上扫描定阈值，回填 `pseudo_labels1.js`，重跑得到新全量结果，再在独立验证集上计算指标。

**关键：阈值改动之后不需要重新判读。** `VV_pre` / `VH_pre` / `VV_post_c` / `VH_post_c` 四列已在导出列里（`validation_review.js:1449`），本地用这四列重算 `new_label` 即可，不必回 GEE、不必重新目视。

调阈值与精度评价必须用不同事件——否则扫描时挑中的参数在评价时天然占优。【改动42】已有此迹象：`VH_pre` 的 AUC 仅 0.12（四个里最差），单参数扫描却把 F1 从 .677 推到 .758，被选中靠的是 F1，不是判别力。

**层归属会过期。** `stratum` 由当前阈值决定（`highFlood01` / `mediumFlood01` 见 `validation_review.js:1100-1101`，`cutPreWater` 见 `:1089-1091`）。阈值改动后，按层统计的数字（如「第 3 层误删率」）反映的是抽样时的阈值口径，须在分析文档中写明，不能靠重跑刷新（重跑即重判，形成循环）。

### 本文尚未覆盖、须先定口径的两件事

1. **漏检点层。** 【改动44】已新增第 5 层 `missed_optical`，但**仍缺一类**。原状：`samplable = knownArea.or(droppedByNewThr)`，只覆盖「新规则有标签」与「旧规则判洪被删」两类，`new_label = 0 且 reference = 1` 的点按构造抽不到，因此 Recall 恒为 1.000 是结构性产物。
   - **已补**：`samplable` 追加 `.or(missedByOptical)`，定义「SAR 六条全过 ∧ 有 S2 ∧ 光学判非水 ∧ 非永久水 ∧ 坡度合格」，这类像元最终 `label = −1`。口径含义是「S2 判非水是否否掉了真淹没」，矛盾指向光学项，**不是**四条 S1 阈值的松紧。
   - **勘误**：本文上一版把候选定义写成 `oldSarFlood01 ∧ ¬s1Valid`，但 `oldSarFlood01` 末尾已带 `.and(s1Valid)`，该式**恒为空集**，抽不出任何点。
   - **仍缺**：「SAR 相对下降本身不成立」这一类真洪（旧规则漏检，与四条绝对阈值无关）目前没有任何层覆盖。
2. **非随机分层的加权口径。** 每层固定配额，每点代表的像元数差几个量级，直接并入 Precision / Recall 会带抽样偏差。新增任何一层之前须先定该层的统计口径，否则扩点只是增加不可解释的点数。**这一条先于第 1 条生效**：第 5 层已落地，但它的 Recall 口径正卡在这条上——在定下加权口径之前，第 5 层的判读结果只能作「漏检候选真洪占比」描述，不能写进 `Recall`。
