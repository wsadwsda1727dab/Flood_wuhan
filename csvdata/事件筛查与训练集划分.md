## 1. 结论速览

- **19 个事件全部成功**（`status=OK`，无 skipped），12 个事件的 `s1_valid_cover` 达 1.000；
- **洪涝面积与雨量的一致性跨度达 34 倍**（每 100 mm 雨量对应 1.2 ~ 41.4 km²），说明各事件的标签口径**不可直接混用**；

## 5. 训练 / 验证划分建议

### 主验证集（从 A 类留出 3 个：跨雨量级 + 跨年份）

| 事件 | 雨量 | 留出理由 |
|---|---|---|
| Wuhan_2020_0705 | 432.5 mm | 最大事件（92.7 km²），检验大洪水表现 |
| Wuhan_2019_0620 | 208.0 mm | 中等事件，High/Med 均衡（1012 / 843） |
| Wuhan_2017_0824 | 50.0 mm | 最小事件（9.7 km²）+ **L1C 口径迁移测试** |

### 训练集（其余 7 个）

`2016_0630`、`2017_0405`、`2018_0630`、`2020_0628`、`2021_0510`、`2024_0621`、`2025_0607`

- 覆盖 2016–2025 的 6 个年份段、雨量 100 ~ 560 mm；
- 保留 1 个 L1C/TOA 事件（`2018_0630`），让模型见过跨口径特征；评价时按 `s2_source` 分层报告。
- 样本量：7 事件 × 约 4000 条（2000 正 + 2000 负）≈ **2.8 万条**，正类充足。

### 压力测试集（B 类 7 个）

只评估、不训练。建议单独报告一组指标，与主验证集对比。

### 一条硬规矩

**验证必须按事件留出，不能把同一事件的像元随机分到训练 / 验证**——同一事件相邻像元空间自相关极强，随机划分会让精度虚高。若要在训练事件内部再划验证，请用**空间分块**（例如 5 km 网格，训练块与验证块不重叠），并同时报告"按事件留出"和"空间分块"两套结果。

## 6. 机制发现（比个别事件更重要）

### 发现 1：洪涝面积的上限由"S2 是否测到水"决定，而不是 SAR 阈值

4 个低面积事件（`2021_0823`、`2022_0627`、`2023_0618`、`2023_0719`）有三个共同特征：

1. `n_medium_flood_px = 0`（没有任何 SAR 单证据像元）；
2. `s2_valid_px ≈ 100 万`，即 S2 后窗口合成**全域有效**；
3. 把 VV 阈值从 −4.0 放宽到 −3.5，洪涝像元只增加 4% ~ 23%（`2022_0627`：225 → 235）。

机制：洪涝类 = `SAR强变化 ∧ 非永久水体 ∧ 低坡度 ∧ (光学水 ∨ 无S2)`。
当 S2 全域有效时，条件退化为"必须有光学水"，于是**所有 SAR 判暗但 S2 判没水的像元被彻底排除**，而 18 天后窗口的 MNDWI 中值往往已经反映退水状态 → 面积被严重压缩。第 3 点的证据表明瓶颈不在 SAR 阈值（放宽阈值几乎不涨），而在光学条件。

### 发现 2：反方向的不一致同样来自 S2 可用性

`Wuhan_2018_0518` 面积比 41.4（全场最高），其 `s2_valid_px` 仅 33 万（约 33% 覆盖），大量像元因"无 S2"落入 Medium（SAR 单证据）→ 面积相对雨量偏高。同方向的还有 `2016_0601`（S2 有效 11 万）、`2017_0608`（26 万）、`2020_0628`（54 万）。

### 结论

洪涝面积在事件间的可比性，**首先取决于 S2 在事件后窗口的可用性与时间代表性，其次才是 SAR**。在修复这一点之前，各事件的标签不宜直接合并训练。

## 7. 建议的修复步骤

### 第一步（推荐，改一行）：缩短 S2 窗口至"事件后最早 3~5 天"

与 S1 的"事件后最早 8 天"逻辑对齐，让 MNDWI 中值贴近洪峰。预期效果：

- 4 个低面积事件的 High 类明显增加 → 面积回到合理区间；
- S2 景数变少、云洞变多，部分像元转入 Medium → 面积进一步回升；
- 与 S2 稀疏事件（如 `2018_0518`）的口径差距缩小。

建议先重跑 `2021_0823`、`2022_0627`、`2023_0618`、`2023_0719` 四个事件 + `2020_0705` 作对照，观察"面积/雨量"是否收敛到 6~31 的区间。

### 第二步（可选）：放宽 Medium 的定义

把 Medium 改为"SAR 强变化 ∧ 非永久水体 ∧ 低坡度"（不再要求"无 S2"），并把"S2 有效但无水"单列为一档置信度（例如 `conf_flood=1` 的弱版）。这样洪涝范围由 SAR 主导、S2 只用于置信度分档，跨事件一致性更好；代价是失去了"S2 明确反对"时的否决权。

### 第三步：修两个覆盖不足的事件

| 事件 | 现窗口 | 建议 |
|---|---|---|
| Wuhan_2016_0601 | 后窗 06-01 ~ 06-19（实际只取到 06-11 单日） | 手工指定更长的后窗口（如 `postEnd: '2016-06-25'`），或把"最早 8 天"改成"最早 2 条不同轨道" |
| Wuhan_2024_0628 | 前窗 05-19 ~ 06-09（仅 4 景） | 延长 `PRE_WINDOW_DAYS`（24 → 36）或手工指定 `preStart`，让前窗覆盖到第 3 个日期 |

### 第四步：加一列诊断量，区分两种失败模式

当前 summary 无法区分"S2 把像元挡掉了"与"SAR 本来就没测到水"。建议增加：

```js
summary.n_sar_cand_px = sarFlood01.reduceRegion({
  reducer: ee.Reducer.sum(), geometry: geom,
  scale: SAMPLE_SCALE, bestEffort: true, maxPixels: 1e10}).values().get(0);
```

即**只带 `s1Valid` 的 SAR 候选数**（不含坡度 / 永久水体 / 光学条件）。判读：

- 候选数上万而最终洪涝只有几百 → 被后续条件过滤（可修）；
- 候选数本身只有几百 → 过境时水已退去（物理限制，只能接受或换数据源）。

## 8. 数据口径提醒

1. **`s2_valid_px` 不在 100 m 网格上**：全 ROI 时该列约为 1,000,485，而 ROI 实际面积是 8,581.6 km²（≈ 858,157 个 100 m 格）。因此不要用它换算面积。
2. **面积一律用 `flood_area_km2` / `valid_area_km2`**（原生分辨率像素面积加权）。`n_flood_px × 0.01` 会系统性偏大约 16%（100 m 网格重采样时部分覆盖的网格被整格计入），两个口径不要混用。
3. **`n_flood_px` 的用途是"抽样池网格数"**，与 `sample_count` 配套（`stratifiedSample` 就在 100 m 网格上抽样）。
4. `Wuhan_2017_0608` 的 `rain_ref_mm` 为空（原文档只写"局部暴雨，中心城区无明显渍水"），该事件不参与雨量—面积一致性分析。
5. `Wuhan_2025_0607` 的 `rainfall` 字段注明雨量来自"6 月 21 日数据"，与事件窗口（6 月 7–9 日）不符，需回查 `doc/2016_2025.docx`。
6. **2016–2018 的部分事件走 L1C/TOA**（本批为 `2016_0601`、`2017_0824`、`2018_0518`、`2018_0630`），与 2019 年之后的 SR/L2A 不是同一辐射口径，跨年合并必须按 `s2_source` 分层。

## 9. 复现方法

```powershell
# 读取汇总表并计算面积/雨量比
$rows = Import-Csv 'csvdata\Wuhan_2016_2025_Flood_Event_Summary.csv'
$rows | ForEach-Object {
  $rain = if ($_.rain_ref_mm -match '^[\d.]+$') { [double]$_.rain_ref_mm } else { $null }
  [pscustomobject]@{
    event   = $_.event_id
    cover   = [double]$_.s1_valid_cover
    km2     = [double]$_.flood_area_km2
    per100  = if ($rain) { [math]::Round([double]$_.flood_area_km2 / ($rain/100), 1) } else { $null }
    high    = [double]$_.n_high_flood_px
    med     = [double]$_.n_medium_flood_px
    sens    = [double]$_.flood_sens_ratio
  }
} | Sort-Object per100 | Format-Table -AutoSize
```

| 派生指标 | 定义 |
|---|---|
| 洪涝占比 % | `flood_area_km2 ÷ valid_area_km2 × 100` |
| 面积/雨量比 | `flood_area_km2 ÷ (rain_ref_mm ÷ 100)`，单位 km²/100mm |
| 光学佐证占比 | `n_high_flood_px ÷ n_flood_px` |
